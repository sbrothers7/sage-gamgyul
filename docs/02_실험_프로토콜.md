# 실험 프로토콜

무엇을, 어떤 순서로, 왜 하는지 정리한 문서입니다.
실험을 시작하기 전에 한 번 읽고, 진행하면서 다시 확인하세요.

---

## 이 연구가 답하려는 질문

> 발표된 감귤 병해 AI 모델을 그대로 구현했을 때, 학습에 쓰이지 않은
> 새 감귤 이미지에서도 논문이 보고한 성능이 유지되는가?

답은 하나의 숫자로 나옵니다. **일반화 격차 = (재현 성능) − (일반화 성능)**

---

## 실험 설계

Mahapatra et al. (2026)의 intra-dataset / cross-dataset 대조 설계를 따릅니다.
같은 모델 하나를 네 가지 조건에서 평가합니다.

| 조건 | 데이터 | 배경 | 무엇을 보는가 |
|---|---|---|---|
| 1 | source_A 시험셋 | 원본 | **재현 성능** — 논문 수치가 재현되는가 |
| 2 | source_B 전체 | 원본 | **일반화 성능** — 새 이미지에서도 되는가 |
| 3 | source_A 시험셋 | 제거 | 배경을 지워도 재현 성능이 유지되는가 |
| 4 | source_B 전체 | 제거 | 배경이 성능 저하의 원인이었는가 |

조건 3, 4가 있는 이유:

모델이 병반을 배운 게 아니라 **촬영 환경(배경)** 을 배웠을 수 있습니다.
배경을 지웠을 때 조건 1의 성능이 크게 떨어진다면, 그 모델은 애초에
병을 진단한 것이 아니라 "이 사진이 어느 데이터셋에서 왔는지"를
맞히고 있었다는 뜻입니다.

## 실행 순서

### 0단계 — 파이프라인 점검 (데이터 없이)

진짜 데이터를 구하기 전에 코드가 도는지 먼저 확인합니다.

```
python make_test_data.py
python run_1_prepare.py
python run_2_train.py
python run_3_evaluate.py
python run_4_gradcam.py
python run_5_report.py
python make_test_data.py --clean
```

여기서 나오는 숫자는 **연구 결과가 아닙니다.** 가짜 그림으로 만든
배관 점검용일 뿐입니다. 확인이 끝나면 반드시 `--clean` 으로 지우세요.

### 1단계 — 데이터 준비

```
python run_1_prepare.py
```

- 이미지 목록을 만들고 A를 학습/검증/시험으로 나눕니다 (7:1.5:1.5).
- **층화 분할**을 씁니다. 병해별 비율을 유지해서 한쪽에 몰리는 것을 막습니다.
- A와 B에 같은 이미지가 있는지 검사합니다. 있으면 **반드시 지우세요.**
- 배경 제거 사본을 만듭니다.

### 2단계 — 학습 (재현)

```
python run_2_train.py
```

- ImageNet 사전학습 모델을 가져와 감귤 병해에 맞게 미세조정합니다 (전이학습).
- 검증 F1이 가장 높은 시점의 모델을 저장합니다.
- 검증 성능이 7회 연속 안 오르면 자동으로 멈춥니다.

**여기서 나온 정확도가 원 논문 수치와 비슷해야 합니다.**
너무 낮으면 데이터가 부족하거나 설정이 잘못된 것입니다.
너무 낮은 채로 3단계를 진행하면 "일반화가 안 된다"가 아니라
"애초에 학습이 안 됐다"가 되어 버립니다.

### 3단계 — 일반화 검증 ★핵심★

```
python run_3_evaluate.py
```

네 조건의 성적표와 최종 비교표가 나옵니다.
**이 출력이 연구의 답입니다.** 화면을 캡처해서 연구노트에 붙이세요.

### 4단계 — 판단 근거 확인

```
python run_4_gradcam.py
```

- 모델이 이미지의 어디를 보고 판단했는지 히트맵으로 만듭니다.
- **잎 집중도**를 계산합니다. 1에 가까우면 잎을, 0에 가까우면 배경을 본 것입니다.
- A와 B의 집중도를 비교하면 성능 저하의 원인을 설명할 수 있습니다.

주의: 배경이 잎과 색이 비슷하면 잎 분리에 실패합니다. 실패한 이미지는
자동으로 평균에서 빠지며 화면에 경고가 뜹니다. **유효 표본이 절반에
못 미치면 이 수치는 논문에 쓰지 마세요.**

### 5단계 — 그림과 표

```
python run_5_report.py
```

`results/figures/` 에 그림 4종이 생깁니다.
`fig3_condition_comparison.png` 가 논문의 대표 그림이 될 것입니다.

## 결과를 어떻게 해석할 것인가

### 일반화 격차가 클 때 (20%p 이상)

가설이 지지되었습니다. 다음을 확인해서 원인을 좁히세요.

1. `fig4_per_class_drop.png` — 어떤 병해에서 특히 많이 틀렸는가?
2. 혼동행렬 — 무엇을 무엇으로 착각했는가?
3. 잎 집중도 — 시선이 잎 밖으로 흩어졌는가?
4. 배경 제거 조건 — 배경을 지우니 격차가 줄었는가?

4번에서 격차가 줄었다면 **"배경 의존이 원인"** 이라는 강한 결론을 낼 수 있습니다.

### 일반화 격차가 작을 때 (5%p 미만)

성급하게 "일반화가 잘 된다"고 결론 내지 마세요. 먼저 의심할 것:

- **B가 A와 정말 다른가?** 같은 데이터셋에서 가져왔거나, 촬영 조건이
  비슷하면 격차가 안 생기는 게 당연합니다.
- **B의 장수가 너무 적지 않은가?** 병해별 15장 미만이면 우연일 수 있습니다.
- **A와 B에 중복이 없는가?** 1단계 검사를 다시 확인하세요.

이 셋을 다 확인했는데도 격차가 작다면, 그것 자체로 의미 있는 결과입니다.
"전이학습 기반 감귤 병해 모델은 예상보다 강건했다"는 결론도 훌륭한 논문이 됩니다.

### 격차가 음수일 때 (B가 더 높음)

거의 항상 문제가 있다는 신호입니다. B가 A보다 쉽거나, 중복이 있거나,
라벨이 잘못됐을 가능성을 순서대로 점검하세요.

## 반드시 지켜야 할 원칙

**1. 시드를 바꾸지 마세요.**
`config.yaml` 의 `seed: 42` 는 재현성을 위한 것입니다. 결과가 마음에
안 든다고 시드를 이것저것 바꿔 보고 제일 좋은 것만 쓰면, 그것은
연구가 아니라 조작입니다.

**2. source_B를 학습에 쓰지 마세요.**
단 한 장이라도 B가 학습에 들어가는 순간 이 연구는 무효가 됩니다.

**3. 결과를 먼저 정하고 실험하지 마세요.**
"일반화가 안 될 것이다"라는 가설을 세운 것이지, 결론을 정한 게 아닙니다.
반대 결과가 나와도 그대로 보고하세요.

**4. 모든 실행을 연구노트에 기록하세요.**
언제, 어떤 설정으로, 어떤 결과가 나왔는지. `docs/03_연구노트.md` 를 쓰세요.

## 실험 조건을 바꿔 보고 싶다면

`config.yaml` 만 고치면 됩니다. 코드는 건드리지 마세요.

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| 다른 모델로 바꾸기 | `model.name` |
| 학습을 더 오래 | `train.epochs` |
| 병해 종류 추가 | `classes` (폴더도 같이 만들 것) |
| 학습이 느릴 때 | `train.batch_size` 를 8로 |
| 메모리 부족 오류 | `train.batch_size` 를 4~8로 |

여러 모델을 비교하려면 `model.name` 을 바꿔가며 2~5단계를 반복하고,
매번 `results` 폴더를 다른 이름으로 복사해 두세요.
