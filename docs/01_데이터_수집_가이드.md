# 데이터 수집 가이드

이 연구는 **두 종류의 데이터**가 필요합니다. 둘의 성격이 다르다는 점이 핵심입니다.

| 구분 | 이름 | 용도 | 어디서 |
|---|---|---|---|
| A | `source_A` | 원 논문 재현 | 논문이 쓴 공개 데이터셋 |
| B | `source_B` | **일반화 검증** | 직접 수집한 새 감귤 이미지 |

**B가 A와 충분히 달라야 이 연구가 성립합니다.** 같은 데이터셋을 둘로 쪼개면
연구가 아니라 그냥 학습/시험 분할입니다. 반드시 **출처가 다른** 이미지여야 합니다.

---

## 폴더 구조

이 구조를 정확히 지켜야 합니다. 폴더 이름이 곧 정답 라벨이 됩니다.

```
data/raw/
├── source_A/
│   ├── healthy/      ← 건전한 잎 사진들
│   │   ├── 0001.jpg
│   │   └── ...
│   ├── canker/       ← 궤양병
│   └── greening/     ← 황룡병(HLB)
└── source_B/
    ├── healthy/
    ├── canker/
    └── greening/
```

주의할 점:

- 폴더 이름은 `config.yaml` 의 `classes` 와 **글자 하나까지 똑같아야** 합니다.
- 대소문자를 구분합니다. `Healthy` 와 `healthy` 는 다릅니다.
- 파일 형식은 jpg, png, bmp, webp 모두 됩니다.
- 하위 폴더를 더 만들어도 됩니다. 알아서 다 찾습니다.

---

## A: 재현용 데이터 구하기

재현 대상 논문은 **Devora-Guadarrama et al. (2025)** 입니다.
이 논문은 Kaggle의 공개 감귤 데이터셋을 사용했습니다.

### 받는 방법

1. Kaggle 계정을 만듭니다 (무료). https://www.kaggle.com
2. 검색창에 다음 키워드로 찾습니다.
   - `citrus leaf disease`
   - `citrus canker huanglongbing`
   - `citrus plant disease dataset`
3. 다운로드한 뒤 병해별로 위 폴더 구조에 맞게 넣습니다.

### 확인할 것

받은 데이터의 **병해 이름이 논문과 맞는지** 확인하세요. 데이터셋마다
이름이 다릅니다. 예를 들어 황룡병은 다음처럼 여러 이름으로 불립니다.

- `greening` / `HLB` / `Huanglongbing` / `citrus_greening`

어느 것을 쓰든 상관없지만, **폴더 이름과 `config.yaml` 이 일치**해야 합니다.

### 목표 장수

병해별 최소 50장, 가능하면 100장 이상이 좋습니다.
너무 적으면 학습이 안 되고, 원 논문 재현도 어렵습니다.

---

## B: 일반화 검증용 새 감귤 이미지 ★가장 중요★

여기가 이 연구의 승부처입니다. **A와 다른 조건**에서 얻은 이미지여야 합니다.

### 방법 1 — 직접 촬영 (가장 좋음)

제주 감귤 농가나 학교 온실에서 직접 찍습니다.

촬영 시 지켜야 할 것:

- **한 장에 잎 하나**가 크게 나오게 찍습니다.
- 스마트폰으로 충분합니다. 오히려 실제 사용 환경에 가깝습니다.
- **촬영 조건을 일부러 다양하게** 합니다. 맑은 날, 흐린 날, 아침, 오후,
  그늘, 직사광선을 섞으세요. 이게 A와의 차이를 만듭니다.
- 배경을 통제하지 마세요. 흙, 다른 잎, 하늘이 같이 나와도 괜찮습니다.
  오히려 그래야 실제 상황입니다.

**병해 판정을 반드시 전문가에게 확인받으세요.** 사진만 보고 스스로
황룡병이라고 판단하면 안 됩니다. 정답이 틀리면 연구 전체가 무너집니다.

- 제주특별자치도 농업기술원 (감귤 담당)
- 국립원예특작과학원 감귤연구소
- 지역 농업기술센터

이분들께 사진을 보내 확인받고, **누구에게 언제 확인받았는지 기록**하세요.
연구노트에 남기면 논문 신뢰도가 크게 올라갑니다.

### 방법 2 — 다른 공개 데이터셋

직접 촬영이 어렵다면, A와 **다른 출처**의 공개 데이터셋을 씁니다.

- PlantVillage (Kaggle / GitHub) — 감귤 항목이 있는지 확인 필요
- Mendeley Data — `citrus disease` 로 검색
- Roboflow Universe — `citrus` 로 검색
- 논문 부록으로 공개된 데이터셋

**같은 데이터셋을 A와 B로 나눠 쓰면 안 됩니다.** 반드시 다른 출처여야 합니다.

### 실제로 써 본 다운로드 도구

공개 데이터셋은 보통 GitHub, Kaggle, Hugging Face 셋 중 하나에 있습니다.
각각 받는 방법이 다릅니다.

**GitHub 저장소 (git sparse-checkout)** — 저장소 전체가 아니라 필요한
폴더만 받을 때 씁니다.

```bash
git clone --depth 1 --filter=blob:none --sparse <repo-url>
cd <repo>
git sparse-checkout set <필요한-폴더-경로>
```

**Kaggle (`kagglehub`)** — 공개 데이터셋은 로그인 없이도 받아집니다.

```bash
pip install kagglehub
python -c "
import kagglehub
path = kagglehub.dataset_download('작성자/데이터셋이름')
print(path)
"
```

비공개거나 대회 데이터셋이면 `~/.kaggle/kaggle.json` (Kaggle 계정 설정에서
발급) 이 있어야 합니다.

**Hugging Face Hub** — 토큰이 필요할 수 있습니다.

```bash
pip install -U huggingface_hub
huggingface-cli login   # 토큰 붙여넣기
```

토큰은 `~/.cache/huggingface/token` 에 저장됩니다. **절대 config.yaml 이나
코드에 직접 적지 마세요.** 저장소에 커밋되어 유출됩니다.

> **주의**: 받은 데이터를 그대로 `data/raw/source_A` 나 `source_B` 에
> 넣지 말고, 먼저 `data/datasets/<데이터셋이름>/` 에 원본을 보관한 뒤
> 필요한 병해 폴더만 복사해 넣으세요. 어디서 받았는지 나중에도 알 수
> 있고, 잘못 넣었을 때 되돌리기 쉽습니다. (`data/datasets/` 는
> `.gitignore` 에 들어 있어 저장소에는 올라가지 않습니다.)

### 목표 장수

병해별 20~30장이면 충분합니다. B는 학습에 쓰지 않고 평가만 하므로
A만큼 많을 필요가 없습니다. 다만 **너무 적으면 우연에 좌우**되므로
병해별 최소 15장은 확보하세요.

## 넣고 나서 반드시 할 일

```
python run_1_prepare.py
```

이 명령이 자동으로 다음을 검사합니다.

1. 병해별 장수가 충분한지
2. 폴더 이름이 설정과 맞는지
3. **A와 B에 똑같은 이미지가 들어갔는지** ← 가장 중요

3번이 걸리면 반드시 지우세요. A와 B에 같은 사진이 있으면
"학습에 쓰지 않은 이미지로 검증했다"는 주장이 거짓이 됩니다.
이것을 **데이터 누출(data leakage)** 이라고 하며,
Kapoor & Narayanan (2023)이 17개 분야 294편의 논문에서 발견한 문제입니다.

## 데이터 출처 기록표

논문에 반드시 넣어야 합니다. 지금부터 채워 두세요.

| 구분 | 출처 이름 | URL 또는 촬영 장소 | 촬영/공개 시기 | 장수 | 라벨 확인자 |
|---|---|---|---|---|---|
| A | Citrus Leaves Dataset (Rauf et al., 2019, Mendeley) | <https://github.com/ai-agriculture-circuits-and-systems/citrus_leaves> | 2019 원본 공개 | 425 (healthy 58 / canker 163 / greening 204) | (미확인 — 전문가 확인 필요) |
| B | Plant Village Orange — Huanglongbing (Citrus Greening) | <https://github.com/ai-agriculture-circuits-and-systems/Plant_Village_Orange> | PlantVillage 원본 공개 | 11014 (greening만; healthy·canker 없음) | (미확인 — 전문가 확인 필요) |

> B는 greening(황룡병) 병해만 있습니다. healthy·canker는 B에 없어
> 그 두 병해는 일반화 검증이 안 됩니다. 3종 모두 검증하려면 healthy·canker
> 사진이 있는 다른 출처를 추가로 구해야 합니다.

**시도했지만 쓰지 않은 것**: Kaggle `dtrilsbeek/citrus-leaves-prepared`
(`kagglehub.dataset_download`로 받음). 병해별 장수(healthy 58 /
canker 163 / greening 204)가 위 A와 완전히 같아 **같은 원본의 재가공본**으로
판단, B로도 A의 대체로도 쓰지 않음. `data/datasets/citrus-leaves-prepared/`
에 원본만 보관.

> Kamilaris & Prenafeta-Boldú (2018)는 농업공학 리뷰에서 데이터의 출처와
> 전처리를 부수적 사항이 아니라 **핵심 보고 항목**으로 다룹니다.
> 이 표를 성실히 채우는 것만으로도 논문의 격이 달라집니다.
